# Launch & Defend — Architecture

A branching narrative cybersecurity quiz built for a university open-house event. Players act as a developer responding to a live security incident, making decisions that affect a simulated user base. Runs on **Cloudflare Workers + Assets** with Google OAuth and a D1 database.

## Startup Flow

```
Browser loads index.html
  └─ loads js/script.js
       └─ boot animation begins (terminal lines, progress bar)
            └─ Promise.all([
                 fetch('js/index.json'),    ← path list
                 fetch('js/i18n.json'),     ← all UI strings
                 fetch('/api/me')           ← logged-in user or null
               ])
                    └─ _finishBoot()
                         ├─ PATHS, I18N, USER loaded
                         ├─ LANG = localStorage('ld.lang') || 'th'
                         ├─ if !USER        → renderLogin()
                         ├─ if !USER.filled → renderQuestionnaire()
                         └─ else            → renderPathSelect()
                                                  └─ user picks path
                                                       └─ loadPath(id)
                                                            └─ fetch('js/paths/{LANG}/{id}.b64')
                                                                 └─ decode → NODES, ENDINGS, AXES
                                                                      └─ toStart() → begin() → finish()
```

The boot screen has a **two-gate** system: the animation timer and the data Promise.all must both resolve before `_finishBoot()` is called.

## Screens

| Screen | Trigger | Render function |
|---|---|---|
| `login` | no authenticated user | `renderLogin()` |
| `questionnaire` | user logged in but profile not filled | `renderQuestionnaire()` |
| `select` | profile complete / "Back to start" | `renderPathSelect()` |
| `start` | path loaded | `renderStart()` |
| `play` | begin() called | `renderPlay()` → `renderChoose()` or `renderConsequence()` |
| `result` | finish() called | `renderResult()` |

`UI.screen` holds the current screen. `render()` dispatches to the right function.

## Worker API Routes (worker.js)

Built with **Hono**. All routes under the Cloudflare Worker; static assets served by Cloudflare Assets.

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/me` | Returns the logged-in user object from the JWT cookie, or 401 |
| `GET` | `/api/auth/google` | Redirects to Google OAuth consent screen |
| `GET` | `/api/auth/google/callback` | Exchanges code for tokens, upserts user in D1, sets JWT cookie |
| `POST` | `/api/profile` | Saves questionnaire answers (school, age, referral) for the current user |
| `POST` | `/api/scores` | Saves a completed run (path, score, axes, ending) to D1 |
| `GET` | `/api/scores` | Returns scores for the current user |
| `GET` | `/api/logout` | Clears the JWT cookie |

---

## Auth Flow

1. User clicks "Sign in with Google" → browser hits `GET /api/auth/google`
2. Worker redirects to `https://accounts.google.com/o/oauth2/v2/auth` with `client_id`, `redirect_uri`, `scope=openid email profile`
3. Google redirects back to `GET /api/auth/google/callback?code=...`
4. Worker exchanges code for tokens via `https://oauth2.googleapis.com/token`
5. Worker decodes the `id_token` JWT to get `sub`, `email`, `name`, `picture`
6. Worker upserts the user row in D1 (`users` table, keyed on `google_id`)
7. Worker issues a signed JWT cookie (`ld_session`) containing `{id, email, name, picture, filled}`
8. All subsequent API calls verify this cookie via Hono's JWT middleware

Credentials (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `JWT_SECRET`) are set as Worker secrets in the Cloudflare dashboard — never in `wrangler.toml`.

## D1 Schema (schema.sql)

```sql
CREATE TABLE IF NOT EXISTS users (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  google_id   TEXT UNIQUE NOT NULL,
  email       TEXT,
  name        TEXT,
  picture     TEXT,
  school      TEXT,
  age         INTEGER,
  referral    TEXT,
  filled      INTEGER DEFAULT 0,
  created_at  TEXT DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS scores (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER REFERENCES users(id),
  path_id    TEXT,
  score      INTEGER,
  ending     TEXT,
  axes       TEXT,   -- JSON blob
  lang       TEXT,
  created_at TEXT DEFAULT (datetime('now'))
);
```

Run migrations against production with:
```bash
npx wrangler d1 execute openhouse_quizz --remote --file=schema.sql
```

## i18n System

### Overview

- `js/i18n.json` — all UI chrome strings, keyed by language: `{th: {key: "..."}, en: {key: "..."}}`
- `js/paths/th/` and `js/paths/en/` — full separate path data files per language
- `LANG` global — `'th'` or `'en'`, persisted in `localStorage('ld.lang')`
- `I18N` global — loaded once at boot from `js/i18n.json`

### `t(key, vars)` helper

```js
function t(k, v={}) {
  let s = ((I18N[LANG]||{})[k]) || ((I18N.th||{})[k]) || k;
  for (const [a, b] of Object.entries(v)) s = s.replace('{'+a+'}', b);
  return s;
}
```

Falls back to Thai if the key is missing in the current language. Falls back to the key itself if missing in both.

Supports `{placeholder}` interpolation: `t('reviewDec', {n: 42})` → `"Decision impact: 42 users"`.

### `changeLang(l)`

```js
function changeLang(l) {
  LANG = l;
  localStorage.setItem('ld.lang', l);
  if (UI.screen === 'play' || UI.screen === 'result') {
    S = null;
    loadPath(CURRENT_PATH_ID).then(() => toStart());
  } else {
    render();
  }
}
```

If the player is mid-game or on the result screen, the path is reloaded from the new language folder and the run restarts from the beginning. On all other screens, a plain `render()` is enough since no path data is in use.

### Language toggle

Every screen includes a `#btnLang` button. The `go()` function (called after every render) auto-binds it:

```js
const bl = document.getElementById('btnLang');
if (bl) bl.onclick = () => changeLang(LANG === 'th' ? 'en' : 'th');
```

## Game Engine (script.js)

The engine is pure logic with no DOM access. It runs on a **state object `S`** and a loaded **node graph `NODES`**.

### State object `S`

Created fresh by `newState()` at the start of each run:

```js
{
  users: 1000,        // current simulated user count
  trust: 50,          // 0–100, affects score
  damage: 0,          // 0–100, affects score and ending
  rulesFixed: false,  // flags set by specific choices
  serverMoney: false,
  mfa: false,
  disclosed: 'none',
  covered: false,
  rewrote: false,
  wrongDx: false,
  adminWeak: false,
  axes: { sec:0, speed:0, open:0, long:0 },  // style axes
  history: [],         // log of every decision made
  series: [1000],      // user count at each step (for the graph)
  nodeId: null,
  enterFx: null,
  enterTotal: 0,
  dead: false,
  forcedEnding: null,
  lastNext: null
}
```

### Engine functions

| Function | What it does |
|---|---|
| `enterNode(S, id)` | Moves to a node, applies its `enter` effect, marks `S.dead` if users < DEAD |
| `pick(S, cid)` | Applies a choice's effects to S, logs to `S.history`, returns the record |
| `nextOf(S)` | Returns the next node id, or `'END'` (forces `collapse` ending if dead) |
| `endingOf(S)` | Reads flags on S, returns the ending id (e.g. `'root'`, `'cover'`, `'scarred'`) |
| `scoreOf(S, endId)` | Calculates 0–100 score from users, flags, trust, damage |
| `applyFx(S, fx)` | Applies an effect object `{u, trust, damage, set, axes}` to S |

### Special node overrides

Two nodes have behaviour that depends on state and can't live in static JSON. They're defined directly in `script.js`:

- **`NODE_ENTER`** — the `repeat` node's entry effect changes based on `S.rulesFixed`
- **`NODE_TEXT`** — the `repeat` node's display text changes based on `S.rulesFixed` and `S.wrongDx`

`enterNode` and `renderChoose` check these objects first before falling back to the JSON data.

## Data Format (path JSON files)

Each `js/paths/{lang}/*.json` has this top-level shape:

```json
{
  "title": "...",
  "START_USERS": 1000,
  "DEAD": 200,
  "MAXU": 1200,
  "NODES": { ... },
  "ENDINGS": { ... },
  "AXES": [ ... ]
}
```

### Node shape

```json
"nodeId": {
  "title": "...",
  "tag": "...",
  "text": "...",
  "best": "choiceId",
  "bestWhy": "...",
  "enter": { "u": [[-100, "reason"]], "trust": -5, "damage": 10 },
  "choices": [ ... ]
}
```

`enter` is optional — only nodes that fire an automatic effect on arrival have it.

### Choice shape

```json
{
  "id": "a",
  "label": "...",
  "q": "good",           // "good" | "mid" | "bad" — colour-coded badge
  "out": "...",          // consequence text shown after picking
  "u": [[-60, "..."]],   // user delta + reason chips
  "trust": 5,            // optional trust delta
  "damage": 0,           // optional damage delta
  "set": { "rulesFixed": true },
  "axes": { "sec": 1, "speed": -1 },
  "lesson": "...",       // cybersecurity takeaway
  "next": "nodeId"       // or "END" or "END:endingId"
}
```

### Ending shape

```json
"endingId": {
  "title": "...",
  "desc": "...",
  "tone": "good"   // "good" | "mid" | "bad" — controls colour scheme
}
```

### Axes shape

```json
[
  { "k": "sec", "L": "Security", "R": "Business", "letL": "S", "letR": "B",
    "dL": "...", "dM": "...", "dR": "..." }
]
```

`k` matches a key in `S.axes`. The axis bar on the result screen shows where the player landed between the two poles.

### Path index (js/index.json)

```json
{
  "paths": [
    { "id": "a", "title": { "th": "ร้านค้าออนไลน์ที่คุณสร้างเอง", "en": "The Online Shop You Built Yourself" } },
    { "id": "b", "title": { "th": "...", "en": "..." } }
  ]
}
```

Titles are bilingual objects. The UI reads `p.title[LANG] || p.title.th`.

## Encoding Pipeline

Path JSON files contain questions, answers, and lesson text. To prevent the full answer tree from being plain-readable in the browser's Network tab:

1. **Source files** (`js/paths/th/*.json`, `js/paths/en/*.json`) — human-readable, committed to git
2. **Encoded files** (`*.b64`) — base64 strings, served to the browser, gitignored
3. **`node encode.js`** — run locally and by Cloudflare's build step (`npm run build`)
4. **`.assetsignore`** — excludes `js/paths/**/*.json` from the Cloudflare asset upload

The browser decodes like this:

```js
JSON.parse(new TextDecoder().decode(Uint8Array.from(atob(text), c => c.charCodeAt(0))))
```

`atob()` returns Latin-1 bytes; `TextDecoder` re-interprets them as UTF-8, which correctly handles multi-byte Thai characters.

This is intentionally reversible — it's a friction layer and an easter egg for a cybersecurity audience, not encryption.

## Development Workflow

```bash
npm install             # first time only
node encode.js          # generate *.b64 from all source JSON files
npx wrangler dev        # serve at http://localhost:8787 (Worker + Assets)
```

While actively editing path JSON files, run in a second terminal:

```bash
node watch.js           # auto-encodes on save (uses Node's built-in fs.watch)
```

Wrangler dev serves both the static assets and the Worker locally, including a local D1 database stub. Google OAuth will not work in local dev unless you configure a `localhost` redirect URI in the Google Cloud Console.

## Deployment

Push to `main`. Cloudflare automatically:

1. Runs `npm run build` → `node encode.js` (generates all `.b64` files)
2. Uploads static assets, excluding `js/paths/**/*.json` (via `.assetsignore`)
3. Deploys the Worker (`worker.js`) alongside the assets

The D1 database binding, OAuth credentials (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`), and `JWT_SECRET` are configured in the Cloudflare dashboard — not in `wrangler.toml`.

---

## Adding a New Path

1. Create `js/paths/th/e.json` and `js/paths/en/e.json` following the existing structure
2. Add a bilingual entry to `js/index.json`:
   ```json
   { "id": "e", "title": { "th": "ชื่อเรื่อง", "en": "Scenario Title" } }
   ```
3. If any nodes need state-dependent text or entry effects, add them to `NODE_TEXT` / `NODE_ENTER` in `script.js`
4. Run `node encode.js` to generate the `.b64` files
5. Test locally with `npx wrangler dev`, then push — Cloudflare handles the rest

## Kiosk Mode

Append `?kiosk=1` to the URL. After 50 seconds of inactivity a 10-second countdown appears. At 60 seconds the app resets to the path select screen. Designed for unattended booth demos.
